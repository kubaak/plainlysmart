---
name: verify
description: Reproduce Plainlysmart build, hydration, browser interaction or backend failures and select the correct local checks, static-export server and targeted Playwright suites.
---

Paths below are repository-root relative. Commands run from the root unless specified otherwise.

1. Reproduce the affected route, locale, viewport, theme and configuration state. Inspect `package.json`, `playwright.config.ts`, `playwright.dev.config.ts`, `tests/serve-export.mjs` and the relevant test before choosing checks. Capture console/page errors before navigation as in `tests/console.spec.ts`. Fix the cause and add regression coverage when it captures meaningful behavior.
2. Use root `npm run lint` and `npm run typecheck` for frontend code. For backend changes, run `npm run typecheck` and `npm test` separately from `infra/`: root TypeScript excludes infrastructure. `infra/tests/handler.test.ts` mocks external calls; `infra/tests/stack.test.ts` checks synthesized resources. See `infra/README.md` for backend setup rather than invoking a live API.
3. Validate production with `npm run build` BEFORE `npm test` or targeted `npx playwright test tests/console.spec.ts`. Build creates `out/`; Playwright only starts `node tests/serve-export.mjs`, which serves existing files at `http://127.0.0.1:4173`, resolves `.html`/`index.html` and returns exported `404.html`. It does not build and has no SPA fallback. Rebuild after source or public-variable changes. `reuseExistingServer: false` means port 4173 must be free; stop only servers owned by the current task.
4. Target suites by symptom: `tests/booking.spec.ts` for dialog/contact/UTM; `tests/theme.spec.ts` for theme and first paint; `tests/language-switcher.spec.ts` and `tests/browser-preference.spec.ts` for locale persistence/detection; `tests/motion.spec.ts` for reduced-motion, responsive layout and native controls; `tests/console.spec.ts` for runtime errors. Example: `npx playwright test tests/theme.spec.ts tests/language-switcher.spec.ts`. For development-only React diagnostics run `npx playwright test --config=playwright.dev.config.ts tests/console.spec.ts`; it starts/reuses localhost:3000 outside CI. Confirm any reused server belongs to this checkout and has the intended configuration. Dev omits export mode, so it cannot replace production verification.
5. Windows uses installed Edge (`msedge`); other platforms use Chromium (`npx playwright install chromium` if needed). Default workers are 4 locally/2 in CI. Use `--workers=1` for isolation when investigating a failure. `npm run dev` runs Next dev on port 3000; `npm start` previews `out/` using `serve`, separate from the test server. Contact submission tests require public API/site-key values at build time and intercept their external calls; follow `infra/README.md` for that setup and report skipped coverage.
6. Inspect `test-results/` for failure artifacts and screenshots produced by theme/motion suites. Traces are NOT enabled in the checked-in config; request them explicitly, e.g. `npx playwright test tests/console.spec.ts --trace retain-on-failure`. Dev diagnostics appear in the server terminal; no dedicated application log file is configured. For deployed backend diagnostics, log groups are `/aws/lambda/ps-{stage}-contact-handler` and `ps-{stage}-contact-access-logs` with request IDs/stage outcomes; see `infra/README.md` for limits. Do not use `scripts/verify.js` as a current acceptance suite: it expects old Plainero copy and removed form controls. The README's automatic-build/automatic-trace claims are also stale. Completion reports reproduction, fix, exact checks and outcomes, remaining skips or environment blockers; do not present a dev-only pass as static production coverage.
