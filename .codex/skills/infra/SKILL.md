Paths below are repository-root relative. Read `infra/README.md` sections on configuration, migration and custom domains when relevant; verify details against `infra/lib/contact-stack.ts` (currently 128 MB Lambda, despite the README's 256 MB statement).

1. Inspect `infra/cdk.json` -> `infra/bin/contact.ts` -> `infra/lib/contact-stack.ts`. This is an independent npm package with `infra/package-lock.json`; use Node.js 24 and commands from `infra/`. Configuration is CDK context for `stage`, optional `domainName`/`certificateArn`, and CloudFormation parameters for secret ARN, Brevo lists, sender/notification/reply addresses, booking URL and Turnstile hostnames. Inspect parameter-to-Lambda mappings before changing defaults; production hostname restrictions are documented in `infra/README.md`.
2. Preserve selector/construct IDs: `PlainlySmartContact` selects the stack, while its physical name is `ps-{stage}-contact`. Stage defaults to `prod` and allows 1–32 lowercase letters/digits with single separating hyphens, starting with a letter. Named resources use `ps-{stage}-{purpose}`; contact Lambda/API/access logs are `ps-{stage}-contact-handler`, `ps-{stage}-contact-api`, `ps-{stage}-contact-access-logs`; function logs are `/aws/lambda/ps-{stage}-contact-handler`. Tags are `Project=Plainlysmart`, `ProjectCode=ps`, `Environment={stage}`, `ManagedBy=CDK`. IAM role and bootstrap asset names remain generated. Imported secrets/certificates remain external.
3. Keep changes within this project's resources in the shared account. Secret read access is scoped to the imported ARN, and log write access to the function's log group. The small architecture is HTTP API -> one Node.js 24 Lambda (128 MB, 28 seconds), default-stage throttling 5 requests/second with burst 10, and two 30-day log groups. No VPC, NAT, database, queue or Route 53 zone exists. Assess recurring cost before adding infrastructure; retain the simple architecture unless the requested behavior warrants more.
4. Validate locally: `npm run typecheck`, `npm test`, then `npm run synth -- PlainlySmartContact -c stage=prod` (substitute the intended stage consistently). Tests include mocked handler calls and CDK assertions in `infra/tests/stack.test.ts`; synthesis bundles locally with esbuild and writes `infra/cdk.out/`. No credentials or deployment are needed for default synthesis. Keep generated assets/context and secret values out of commits.
5. When a deployed-state comparison is needed and account access is available, `npm run diff -- PlainlySmartContact -c stage=prod --method template` avoids creating a CloudFormation change set; unlike synthesis it needs AWS reads. Template-only diff has less replacement analysis than a change-set diff. Preserve relevant custom-domain context on comparisons. Never bootstrap, deploy, destroy or alter DNS as validation. Deploy only when the user requests it; review target account, region, stage and diff within that authorized task, without touching unrelated stacks or shared bootstrap resources.
6. Explain risks in the result: changing stage/stack name creates another stack rather than migrating the old one; changing explicit Lambda/log group names may replace resources; both log groups use `RemovalPolicy.DESTROY`, so replacement/deletion loses logs. Domain ownership may block concurrent stacks; imported certificates and secrets are not stack-owned. Completion means local checks pass and the review identifies additions, replacements, deletions, IAM/cost changes and cutover implications, distinguishing synthesized intent from deployed state.
