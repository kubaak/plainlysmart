Paths below are repository-root relative. Read `infra/README.md` for configuration, Brevo setup, responses and delivery limits; use implementation when documentation differs.

1. Trace the affected flow: `src/components/booking.tsx` shares consultation triggers through context, remounts the form on dialog opening, validates with React Hook Form/Zod, then POSTs JSON to `{NEXT_PUBLIC_API_BASE_URL}/contact`. `src/components/Turnstile.tsx` supplies a token with action `contact`; `src/lib/contact-tracking.ts` supplies session UTM attribution, also captured before redirect in `src/components/LocaleEntry.tsx`.
2. Keep the browser and backend contracts aligned with `infra/lambda/validation.ts`. The browser has no company field; the backend accepts optional company. Name/email/message are required; phone and marketing consent are optional. Backend validation additionally normalizes NFC, lowercases email, rejects control characters, restricts locale to `en`/`cs` and caps decoded bodies at 24,000 bytes in `handler.ts`. Retain independent backend validation. Update both `messages/en.json` and `messages/cs.json` for UI states/errors.
3. Preserve the verification and response lifecycle. Missing public API/site-key configuration disables submission with an email fallback. The browser has a 35-second deadline and requires both successful HTTP and `{success: true}`; failed submissions retain the draft and recreate Turnstile. Preserve `noValidate`, accessible field errors, duplicate-submit protection, native dialog focus restoration and scroll cleanup.
4. Follow `infra/lambda/handler.ts`: validate, load configuration/secrets, verify Turnstile, upsert Brevo contact, send internal notification, send localized confirmation. `services.ts` checks Turnstile action AND allowed hostname and uses four-second HTTP deadlines. API Gateway owns CORS in `infra/lib/contact-stack.ts`; Lambda does not duplicate headers. Keep sanitized error envelopes and request-ID/stage-only logs, without payloads, tokens or provider details.
5. Keep private keys in the externally provisioned Secrets Manager JSON (`BREVO_API_KEY`, `TURNSTILE_SECRET_KEY`), read by `infra/lambda/config.ts` through `CONTACT_SECRET_ARN` with a five-minute cache. Public build variables are documented in `.env.example`. Brevo list IDs must be positive and distinct; newsletter membership is added only with consent, while unchecked submissions do not unsubscribe. The optional frontend booking URL and backend `BOOKING_URL` are separate settings. Delivery is synchronous and non-atomic: partial success followed by retry may duplicate email; do not introduce automatic provider retries casually.
6. Validate without real mail: from `infra/`, run `npm run typecheck` and `npm test`; `infra/tests/handler.test.ts` mocks fetch and Secrets Manager. For browser coverage, follow `infra/README.md`'s public test-key build example and run root `npx playwright test tests/booking.spec.ts` against a fresh export. That suite intercepts Turnstile and `/contact`; without public configuration submission coverage skips/returns early. Do not submit against a deployed API as local validation or publish a test-key build. Completion requires relevant contract/error/consent regression coverage and both locale UI states; report skips explicitly.
